I connect the tools small businesses already use and put the automation on top.

CRMs, accounting, shared mailboxes, industry portals — most of the work in a back office is copying data between them. I build the layer in between: connectors, bots and one clear view. Two of those platforms are public, with demos you can click through without an account.

Projects

birdie

The transparency layer for solar installers

A solar installer runs the business across a CRM, accounting, mailboxes, a calendar and dozens of grid-operator portals with their own logins and PDF forms. None of them talk to each other, and grid connections stall because a utility’s follow-up question sits unread in a shared inbox.

  • Connector SDK with 11 adapters (CRM, accounting, Google Workspace, WhatsApp, tariffs, battery IoT) and a polling scheduler with retries and error isolation
  • Utility registration on autopilot: forms prefilled from project data, utility e-mails matched to projects, portal drafts prepared by a Playwright bot and released by a human
  • CRM demo in English and German that runs entirely on mock data — no accounts, no keys

Next.js · TypeScript · Supabase · Playwright · n8n · Anthropic API · vitest · GitHub Actions

botworks

A modular AI bot platform for small businesses

Every “AI assistant” built for one customer ends up as a one-off script nobody can operate, monitor or reuse. botworks treats each task as a bot with a contract and runs all of them on one shared runtime, per tenant.

  • 13 bots (inbox triage, document extraction, dunning, tax prep, reviews…) on one runtime: validation, queue with priorities and retries, connector injection, structured logging
  • Multi-tenant admin panel: bot fleet, connector health, sync logs, billing, compliance — with a database stand-in so it runs without infrastructure
  • Every AI call ships a deterministic offline answer that still passes the bot’s real response schema; the queue falls back to memory when no Redis is configured

TypeScript · Hono · BullMQ / Redis · zod · Next.js · Supabase · Anthropic SDK · vitest · GitHub Actions

How I work

Runs before it’s wired up

Both platforms start with two commands and no credentials. Mock transports and offline answers go through the real parsing code, so what you see in the demo is what ships.

Tested, in CI, documented

Vitest suites, GitHub Actions on every push, READMEs that explain the problem and the architecture, not just the commands. Writing the tests found a real API bug — that’s the point of them.

Automation with a person in the loop

Bots prepare drafts, classify and prefill; a human releases. I’d rather build something an office actually trusts than a demo that submits forms on its own.
